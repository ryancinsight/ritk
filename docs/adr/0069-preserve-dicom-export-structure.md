# 0069 — Preserve DICOM export structure

Status: Accepted

## Context

Real MRI and CT exports preserve their pixels but expose three defects.
Header actions populate absent attributes in sequence items, and the selected
profile rules leave CT provenance fields and irradiation-event UIDs.
Remapped UIDs use a decimal encoding outside the 128-bit UUID arc. Flat
export also accepts a Media Storage Directory object that points at files
the exporter does not write.

## Decision

Apply replacement and emptying rules only to attributes that exist in each
data set. Write Patient Name and Patient ID using their defined PN and LO
value representations. Remove optional SOP Common creation date and time
and nested contribution date, time, and description. Preserve equipment
and reference sequence items. Apply the same deterministic mapping to
Irradiation Event UID in profiles that replace UIDs. Basic retains entity
UIDs according to its existing contract.

Use the first 128 bits of the existing salted SHA-256 digest, set the version
and variant per RFC 9562 UUIDv8, and serialize the unsigned big-endian value
in decimal under `2.25.` per DICOM PS3.5 B.2. This leaves 122 digest bits.
For a fixed salt an identical source UID maps identically across files and
sequence items. The collision probability for two distinct inputs under the
uniform-digest model is 2⁻¹²². A public or guessable salt still allows matching
against known inputs.

Classify flat inputs by their media storage SOP class. Reject each DICOMDIR
as a counted per-file error before assigning any output number. Keep processing
other immediate files and retain the existing statistics schema.

## Alternatives

Dropping whole equipment or reference sequences would lose structural
information. Appending source path components to a filename can expose source
identifiers. Regenerating a file-set index would require a separate export
contract that validates references and publishes the complete file set.

## Migration and verification

Re-export the whole related batch from the originals when moving to the
UUID-based mapping. Do not combine instances generated by different mappings
as one export. Pass the directory containing the images to the flat API and
check per-file errors. The opt-in installed-wheel regression checks real MRI
and compressed CT instance identity, pixels, calibration, geometry, nested
metadata, and media-root rejection. It does not certify general PS3.15
conformance or pixel disclosure safety.

Ryan Clanton approved the follow-up and these behavior changes on
2026-11-22. This change targets the pending 0.8.0 IO and 0.13.0 Python
release alongside ADR 0068.
