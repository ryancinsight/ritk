## RITK-MGH-LPS-CONVENTION-001 — Reconcile MGH RAS geometry with the LPS stored model — todo
- outcome: MGH origins and direction columns agree with the rest of RITK on handedness, so an MGH volume and the same volume read from NIfTI describe the same physical space.
- acceptance: The MGH reader converts the header's RAS `c_ras` and `Mdc` into the stored model's LPS frame and the writer inverts it, or the divergence is recorded as a typed spatial loss; a cross-format test pins the same physical point read through both readers, and `docs/architecture.md` §13 (the `ritk-mgh::spatial` transform) matches the code.
- scope: crates/ritk-mgh/src/spatial.rs, reader, writer, tests; docs/architecture.md §13; docs/book/mgh_format.md
- next: `docs/architecture.md` §5 states the stored model is LPS-millimetre geometry, and §9 gives `ritk-nifti` the RAS-to-LPS row conversion, but §13 has `ritk-mgh::spatial` feed the header's RAS `c_ras` and `Mdc` straight into `Point` and `Direction` with no flip. The reader test `crates/ritk-mgh/src/reader/tests/geometry.rs::test_read_geometry` pins positive origin components `[10.75, 19.25, 29.375]`, i.e. RAS, so the current behavior is deliberate in code and wrong against the stated model. The axis-order reversal this depends on has already landed as its own change. The `Mdc` column-versus-row question is settled against the reference implementation rather than a fixture: nibabel's `MghHeader` declares `('Mdc', '>f4', (3, 3))` as the **transpose** of the direction-cosine matrix and builds `MdcD = hdr['Mdc'].T * hdr['delta']`, so the stored `Mdc` **columns** are the RAS direction cosines and `ritk-mgh::spatial`'s column reading is correct — no transpose is owed. The real divergence is the frame: nibabel builds `vox2ras = from_matvec(MdcD, Pxyz_c - vol_center)`, so `c_ras`/`Pxyz_c` is explicitly **RAS** while the stored model is LPS. Next: negate the x and y components of `c_ras` and the x/y rows of the RAS direction columns on the way into the stored frame, reusing the row-negation idiom of `ritk-nifti::spatial::ras_affine_to_lps_file_axes`, and invert it in `ras_block_from_geometry`; move the reader fixture from RAS to LPS and add a cross-format test that pins one physical point read through both the MGH and NIfTI readers.
