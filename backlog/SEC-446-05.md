## SEC-446-05 — Bound parser header counts by ImageReadBudget — todo
- outcome: Header-declared volume counts and decoded sizes in ritk-mgh, ritk-mif, ritk-codecs and ritk-metaimage are rejected against `ImageReadBudget` with a typed error, instead of failing only when the payload runs short. A MetaImage zlib inflate is today capped only by the header's `DimSize` product (`ritk-metaimage/src/reader.rs:236-247`).
- acceptance: `read_mgh_series`, `read_mif_series`, the JPEG 2000 decode and the MetaImage readers take an `ImageReadBudget` and return a typed error variant for a header `nframes` above `max_series_volumes()` or a decoded size above `max_decoded_bytes()`, before allocating or inflating; each guard has a fixture that fails when the guard is reverted, asserted with `matches!(err, <Error>::<Variant> { .. })`. The `.mif` offset-overrun message (`ritk-mif/src/reader.rs:234`) reads as one sentence.
- scope: crates/ritk-mgh/, crates/ritk-mif/, crates/ritk-codecs/, crates/ritk-metaimage/, and their Cargo.toml edges to ritk-image-io
- next: decide how the crates receive the budget (a `ritk-image-io` dependency edge versus a budget type in the foundation crate) and replace their `anyhow` returns on these paths with a crate error enum. ritk-mgh and ritk-mif have none; ritk-codecs has `SampleError` and `Jpeg2000EncodeError`, but its EBCOT decode path returns `anyhow`. Payload-size guards landed in 4970235a6 and ritk#859.
